REST API Reference

Every HTTP endpoint exposed by the Task Management service, with required inputs and sample request/response payloads. Generated from the current controllers — if you add or change an endpoint, update this page too.

Base URL: http://localhost:8080
No authentication is implemented — every endpoint below is open. All request/response bodies are JSON (Content-Type: application/json) unless noted otherwise (CSV import uses multipart/form-data). Errors share one shape — see Error Responses.
Error Responses

Every failure — validation, not-found, bad input, unexpected exception — is returned as JSON with a matching HTTP status, via a global exception handler.

Not found / bad request (e.g. GET /api/tasks/9999)
{
  "timestamp": "2026-07-26T12:00:00Z",
  "status": 404,
  "error": "Not Found",
  "message": "Task not found: 9999"
}
Validation failure (e.g. POST /api/tasks with no title)
{
  "timestamp": "2026-07-26T12:00:00Z",
  "status": 400,
  "error": "Bad Request",
  "message": "Validation failed",
  "fieldErrors": {
    "title": "must not be blank"
  }
}
Status codes used across this API
200 OK 204 No Content (successful DELETE) 400 Bad Request (validation / illegal argument) 404 Not Found 409 Conflict (duplicate/circular dependency) 500 Internal Server Error (unexpected)
WS/ws/tasks

Persistent WebSocket connection used by the UI to run task searches and receive live create/update/delete notifications without polling. All messages are JSON text frames.

Client → server messages
{"type":"search",         "requestId":"r1", "payload": { "sortBy":"dueDate", "sortDir":"asc", "size":500 } }
{"type":"filter-options", "requestId":"r2" }
{"type":"ping",           "requestId":"r3" }

The payload for search is the same shape as the GET /api/tasks query parameters (as a JSON object instead of a query string).

Server → client messages
{"type":"connected"}
{"type":"search-result",         "requestId":"r1", "data": { "tasks":[...], "total":42, "page":0, "size":500 } }
{"type":"filter-options-result",  "requestId":"r2", "data": { "categories":[...], "programmes":[...] } }
{"type":"pong",                   "requestId":"r3" }
{"type":"error",                  "requestId":"r1", "message":"Invalid message: ..." }
{"type":"task-changed", "changeType":"created", "taskId":42, "task": { ... } }

task-changed is broadcast to every connected browser (unsolicited, no requestId) whenever any client creates, updates, or deletes a task via the REST API. changeType is one of created, updated, deleted.
